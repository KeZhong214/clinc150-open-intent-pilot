# Gate 4 演讲稿（约 10–12 分钟）

## 开场（约 50 秒）

各位老师好，这一轮我从“开放意图分类器”继续往前走，做两件事：第一，训练一个真正融入 B3-H 的门控和拒识模块，叫 B4-AR；第二，把分类器升级成一个有状态、能调用 SQLite 工具的客服 Agent。

先说明边界：BANKING77 的 test 在 Gate 3 已经看过，所以这一轮的 test 是探索性对照，不是新的盲测。B0 和 B3-H 的数字直接来自 Gate 3 的冻结结果。

## 起点（约 1 分钟）

Gate 3 在 BANKING77、GTE、10-shot 上，B0 的 open-set F1 是 0.8081，B3-H 是 0.8306。B3-H 的融合权重是固定 0.5/0.5，这很稳，但它不是可学习的，也不区分输入难度。

所以我想验证两个问题：第一，能不能只用 400 条 support，训练一个按类、按难度变化的融合门控？第二，拒识头能不能比固定阈值更好地处理 OOS？

## B4-AR（约 1 分 30 秒）

B4 的输入是三个已有的量：`P_c` 是多原型分数，`N_c` 是 Top-2 近邻分数，`d_c` 是类内分散度。门控是一个所有类共享的小 MLP，输入是 `[P_c, N_c, P_c-N_c, d_c]`，输出 `g_c`。融合就是 `S_c = g_c P_c + (1-g_c) N_c`。

拒识头是另一个小 MLP，输入是类别置换不敏感的统计量：s1、s1-s2、Top-3 熵、最优类的分散度、两个分支的分歧、门控值等。类别预测还是 argmax S，拒识看拒识头的 known score。

训练时只用 support：每个类 5 条建原型、5 条做 query，两折互换；每个 episode 再屏蔽 6 个类，把它们的 query 当 pseudo-OOS。这样 query 永远不会同时是自己的原型。24 个 episodes，60 + 60 epoch，总共 12.55 秒。

## 结果（约 2 分 30 秒）

先看 validation。B0 的 open-set F1 是 0.734，B3-H 是 0.767，B4-Fusion 是 0.740，B4-Full 是 0.781。B4-Full 比 B3-H 高 1.39 个百分点，OOS recall 从 0.547 提到 0.604。

冻结后只跑一次 test。B4-Full 的 F1 是 0.8369，B3-H 是 0.8306，提升 0.62 个百分点；OOS recall 从 0.637 到 0.658，提升 2.11 个百分点；known routing 基本一样。这个提升不大，我不会把它说成显著突破。

更重要的是 B4-Fusion 单独使用反而退化：test F1 0.820，低于 B3-H 的 0.831。这说明“可训练门控”本身不是收益来源，真正的收益来自拒识头。这是一个诚实的负结果，也让消融更有意义。

门控是不是常量？不是。全类平均门控很低，但 Top-1 类上的门控均值是 0.772，而且按 margin 四分位看，最难的一组是 0.560，最容易的一组是 0.919。越难越偏向近邻分支，越容易越偏向原型分支。梯度也非零，参数确实更新了；checkpoint 在 Demo 里真实加载，不是只写在报告里。

## Agent（约 3 分钟）

第二件事是 Agent。我建了一个虚构的 SQLite 银行库，包含 customers、cards、transfers、disputes、tickets、audit_events。工具包括查卡、查转账、取消转账、激活卡、创建争议、创建工单和转人工。

Agent 是有状态的：先路由 intent，再收集缺失的卡号/交易号，敏感动作先询问确认，确认后才修改数据库；OOS、非本人卡、越权操作都创建高优先级工单转人工。每次工具调用都写审计表。

我做了 6 条真实路由演示：查卡、查转账、取消转账、未知问题、非本人卡、模糊澄清。前三条是成功业务链；第四条是 OOS 转人工；第五条是所有权拒绝；第六条是先澄清再查状态。

指标方面，16 条确定性工具/状态测试是 16/16 完成、16/16 工具调用正确；6 条真实路由演示是 6/6 完成。16 条测试用的是 StubRouter，专门测状态机和工具，不是模型泛化；6 条演示用的是真实 GTE/B3-H/B4，两个数字分开报告。

Demo 是 Streamlit：可以切 B3-H 和 B4-Full，左侧多轮聊天，右侧显示卡、转账、工单、审计；可以展开 Tool timeline，看到真实入参和返回值。截图里取消转账后，Transfers 表里 TXN-2002 确实变成 cancelled。

## 结论（约 1 分钟）

三句话：

第一，B4-Full 在 validation 和探索性 test 上都略优于 B3-H，但提升主要来自拒识头，不是门控。

第二，B4-Fusion 单独退化，说明“把固定融合改成可学习”本身不保证更好；门控确实随难度变化，但需要和拒识头配合。

第三，Agent 的工具、状态、确认、所有权和审计链已经真实闭环；但 test 已看过，单 seed、单数据集，不能外推成通用结论。
